Workflow 1 Deteksi Malware (28 Nodes)

Workflow ini bertugas menginvestigasi berkas baru di workstation endpoint CV Bali Handmade. Menerapkan prinsip confidence-based response agar mitigasi akurat dan tidak menyebabkan salah hapus dokumen kantor.

[Endpoint] → Webhook → Filter → Ekstrak → Dedup → Cek Cache VT → Cache Hit? ├─ (Hit) ──────────────────────────────────────────────────────────┐ └─ (Miss) → Scan VirusTotal → Simpan Cache → VT OK? ┬─ (OK) ────────┼→ MalwareBazaar → MISP → Rangkum Hasil └─ (Fail) → OTX ─┘ [Decision Hub] Rangkum Hasil (+ Process Chain) → Tentukan Otonomi ┬→ Log ke Fleet (Monitoring) └→ Cek Ancaman (AR?) ├─ (True: Kritis) → Get Wazuh Token → Trigger Active Response → Fleet Quarantine ┐ └─ (False: Ambigu/Review) ──────────────────────────────────────────────────────────────┴→ Build Payload → Perlu Notif? → Catat Keputusan Tertunda → AI Generate (Gemini) → Send Telegram (HITL) → Log Alert
Tahap 1: Ingestion, Normalisasi, & Anti-Duplikasi Webhook • Filter • Ekstrak • Dedup
Event berkas baru diterima via HTTP POST dari agen Rust (`soar-agent`) atau Wazuh FIM. Node Filter Alert Malware menyaring berkas noise sistem (seperti `/tmp/` atau swap). Node Ekstrak Alert membedah metadata inti (hash SHA-256, path, agent ID, dan status executable). Node Dedup Alert mencegah duplikasi notifikasi jika ada berkas yang diubah berulang kali dalam jeda singkat.
Tahap 2: Hierarki Intelijen Multi-Sumber (Cache-First & Fallback) Cek Cache VT • Scan VirusTotal • OTX • MalwareBazaar • MISP
Sistem memeriksa Cek Cache VT lokal lebih dulu. Jika hash sudah pernah diperiksa sebelumnya (cache hit), sistem langsung melompati query internet (menghemat kuota API free VT). Jika cache miss, query dikirim ke VirusTotal (70+ engine AV). Jika kuota VT habis (rate-limit 429), sistem otomatis fallback ke OTX Lookup (AlienVault). Selanjutnya, hash selalu diverifikasi silang ke feed komunitas MalwareBazaar dan MISP CIRCL OSINT.
Tahap 3: Jalur Paralel Rantai Proses (Process Chain) Cabang Chain? • Ekstrak Chain • Rangkum Chain
Berjalan di jalur bawah sejajar dengan FIM. Menangkap anomali rantai eksekusi proses mencurigakan (misalnya dokumen Microsoft Office yang tiba-tiba memicu `powershell.exe` atau `cmd.exe` untuk mengunduh payload). Hasil rantai proses ini diintegrasikan ke titik keputusan bersama.
Tahap 4: Engine Keputusan & Dual Mitigasi (Active Response) Tentukan Otonomi • Cek Ancaman • Get Wazuh Token • Fleet Quarantine
Node Tentukan Otonomi membagi severity menjadi: Kritis (≥20 deteksi), Tinggi/Sedang (1-19 deteksi), atau Bersih (0 deteksi). Jika Kritis, node Cek Ancaman memicu Active Response terisolasi ganda: memanggil API Wazuh (`Trigger Active Response`) dan API agen Rust (`Fleet Quarantine`) untuk mengisolasi berkas di workstation target dalam waktu sub-detik.
Tahap 5: Ringkasan AI & Human-in-the-Loop 2-Arah Build Payload • AI Generate • Send Telegram Alert • Catat Keputusan
Jika berkas bersih, alert ditekan 100% (noise suppression). Untuk ancaman terdeteksi, AI Generate (Gemini Flash) menyusun narasi ringkas Bahasa Indonesia yang menjelaskan tipe malware dan rekomendasi tindakan. Bot Telegram mengirim pesan ke admin dengan tombol [Isolasi] / [Abaikan], dan status dicatat di Catat Keputusan Tertunda untuk audit trail.
Poin Menjawab Dosen: "Kenapa tidak pakai satu antivirus saja?" Jawab: "Karena sistem menerapkan defense-in-depth. Lapisan cache menekan latensi dan kuota, konsensus 70+ AV meniadakan bias single-vendor, dan tombol persetujuan Telegram mencegah berkas operasional kantor terhapus salah sasaran."

Workflow 2 Deteksi Phishing (25 Nodes)

Workflow ini bertugas melindungi seluruh workstation dari serangan tautan palsu (phishing). Mengombinasikan jalur cepat reputasi dan sandbox crawling dengan mitigasi aktif otomatis di level jaringan.

[Endpoint Log] → Webhook Phishing → Filter → Ekstrak URL → Cek Cache URL → Cache Hit? ├─ (Hit) ────────────────────────────────────────────────────────────────────────┐ └─ (Miss) → GSB Lookup (Google Safe Browsing) → GSB Threat? │ ├─ (True: Bahaya) ─────────────────────────────────────────────────┼→ Rangkum Phishing └─ (False: Cek Lanjut) → URLScan.io Submit → Tunggu → URLScan Result ┘ [Mitigasi & AI] Rangkum Phishing ┬→ Log ke Fleet (Monitoring) └→ Cek Ancaman ├─ (Bahaya) → Auto Block? ┬─ (True) → Get Wazuh Token → Active Response (Sinkhole Hosts) ┐ │ └─ (False) ────────────────────────────────────────────────────┴→ Build Payload → │ Gemini Generate → Tipe Notif? ┬→ Send Telegram Alert └─ (Aman) → Build Payload Aman ──────────────────────────────────────────────────────────────────┴→ Send Telegram Info
Tahap 1: Ingestion & Cache Reputasi URL Webhook Phishing • Filter • Ekstrak • Cek Cache URL
Menangkap log akses URL dari workstation. Node Cek Cache URL memverifikasi apakah domain tersebut sudah pernah dipindai sebelumnya. Jika domain sudah dikenal di cache lokal, workflow langsung melompat ke Rangkum Phishing tanpa memanggil API eksternal.
Tahap 2: Dual Threat Intel (Jalur Kilat GSB vs. Deep Scan URLScan) GSB Lookup • GSB Threat? • URLScan.io Submit • Tunggu Scan
Sistem memprioritaskan Google Safe Browsing (GSB) sebagai jalur kilat. Jika GSB menyatakan domain berbahaya, sistem langsung merespons dalam ~2,13 detik tanpa menunggu. Namun jika GSB belum memiliki data, workflow mengalihkan pemeriksaan ke URLScan.io untuk melakukan inspeksi mendalam (DOM analysis dan sandbox redirection).
Tahap 3: Mitigasi Aktif Domain Sinkhole di Level Jaringan Cek Ancaman • Auto Block? • Get Wazuh Token • Trigger Active Response
Jika domain terbukti phishing, node Auto Block? memicu Active Response secara otomatis. Wazuh menjalankan script block-domain di endpoint yang memetakan domain berbahaya ke IP 0.0.0.0 di konfigurasi /etc/hosts atau DNS lokal. Hasilnya: seluruh workstation kantor langsung terproteksi dari tautan tersebut seketika.
Tahap 4: Ringkasan AI & Notifikasi Dua Arah Build Payload • Gemini Generate • Tipe Notif? • Send Telegram Alert
Node Gemini Generate merangkum domain yang diblokir, target pemalsuan, dan status mitigasi. Node Tipe Notif? memisahkan alert berbahaya (disertai status blokir) dari informasi URL jinak, lalu mengirimkan laporan real-time ke Telegram analis.

Rangkuman Perbedaan Strategi: Malware vs. Phishing

Aspek Operasional Workflow Deteksi Malware Workflow Deteksi Phishing
Vektor Ancaman Berkas di storage (Downloads, Desktop, USB Flashdisk) Tautan URL di web browser, email, dan WhatsApp Web
Sumber Threat Intel VirusTotal (70+ AV), MalwareBazaar, MISP OSINT, AlienVault OTX Google Safe Browsing v4 (jalur cepat) dan URLScan.io (sandbox)
Bentuk Active Response Isolasi berkas lokal (karantina mandiri via Rust / Wazuh) Domain sinkhole (alihkan domain jahat ke 0.0.0.0 di hosts/DNS)
Kecepatan Respons (MTTR) 0,04 detik (Agen Rust) / 1,68 detik (Wazuh AR) 2,13 detik (Jalur cepat Google Safe Browsing)
Model Human-in-the-Loop Auto-karantina jika skor ≥20; Tombol Telegram jika 1-19 (ambigu) Auto-sinkhole seketika, disusul laporan AI ke Telegram
